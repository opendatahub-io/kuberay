# CodeFlare to KubeRay Migration Testing

This directory contains test resources and scripts for validating the CodeFlare to KubeRay migration logic.

## Overview

When upgrading from ODH/RHOAI versions that used `codeflare-operator` to manage mTLS, NetworkPolicy, and OAuth for RayClusters, the KubeRay reconciler performs an automatic migration. This test suite helps verify that:

1. **CodeFlare-specific configurations are removed:**
   - `create-cert` initContainer
   - `oauth-proxy` sidecar container
   - TLS environment variables (`MY_POD_IP`, `RAY_USE_TLS`, `RAY_TLS_*`)
   - TLS volumes (`ca-vol`, `server-cert`, `proxy-tls-secret`)
   - OAuth proxy ServiceAccountName pattern (`*-oauth-proxy*`)
   - `ray.openshift.ai/oauth-finalizer` finalizer
   - `enableIngress` set to false

2. **Custom configurations are preserved:**
   - User-defined initContainers
   - User-defined sidecar containers
   - Custom environment variables
   - Custom volumes and volume mounts
   - Custom ServiceAccountName (non-CodeFlare patterns)

## Test RayClusters

The `testdata/` directory contains various RayCluster configurations:

### Generic Test Cases

| File | Description |
|------|-------------|
| `raycluster-basic.yaml` | Minimal configuration with no special items |
| `raycluster-custom-initcontainers.yaml` | Custom initContainers that should be preserved |
| `raycluster-custom-serviceaccount.yaml` | Custom ServiceAccountName that should be preserved |
| `raycluster-custom-sidecar.yaml` | Custom sidecar containers (fluentbit, etc.) |
| `raycluster-custom-envvars.yaml` | Custom environment variables |
| `raycluster-custom-volumes.yaml` | Custom volumes and PVCs |
| `raycluster-codeflare-injected.yaml` | Simulates a CodeFlare-managed cluster with the finalizer |

### CodeFlare SDK v0.31.x Test Cases

These test cases match the exact structure generated by codeflare-sdk v0.31.x (used in RHOAI 2.x):

| File | Description |
|------|-------------|
| `raycluster-sdk-basic.yaml` | Default SDK cluster with ODH CA certs, "machine-learning" worker container |
| `raycluster-sdk-gpu.yaml` | SDK cluster with nvidia.com/gpu resources |
| `raycluster-sdk-tolerations.yaml` | SDK cluster with head/worker tolerations |
| `raycluster-sdk-kueue.yaml` | SDK cluster with Kueue local queue label |
| `raycluster-sdk-gcsft.yaml` | SDK cluster with GCS Fault Tolerance (Redis) enabled |
| `raycluster-sdk-full-codeflare.yaml` | **Most comprehensive test** - SDK cluster + CodeFlare injections |

### SDK-Specific Configurations to Preserve

The SDK generates clusters with these specific configurations that **must be preserved** after migration:

1. **Worker container name**: `machine-learning` (not `ray-worker`)
2. **ODH CA certificate volumes**:
   - `odh-trusted-ca-cert` -> ConfigMap `odh-trusted-ca-bundle`
   - `odh-ca-cert` -> ConfigMap `odh-trusted-ca-bundle`
3. **ODH CA certificate mounts**:
   - `/etc/pki/tls/certs/odh-trusted-ca-bundle.crt`
   - `/etc/ssl/certs/odh-trusted-ca-bundle.crt`
   - `/etc/pki/tls/certs/odh-ca-bundle.crt`
   - `/etc/ssl/certs/odh-ca-bundle.crt`
4. **Labels**: `controller-tools.k8s.io: "1.0"`, Kueue queue labels
5. **Lifecycle hooks**: `preStop` with `ray stop` command
6. **imagePullPolicy**: `Always`
7. **Default image**: `quay.io/modh/ray@sha256:...`
8. **rayStartParams**: `block: "true"`, `num-gpus`, `resources`

## Usage

### 1. Setup Test Namespace

```bash
kubectl create namespace test-migration
```

### 2. Apply Test RayClusters

```bash
# Apply all test RayClusters
kubectl apply -f testdata/ -n test-migration

# Or apply specific ones
kubectl apply -f testdata/raycluster-codeflare-injected.yaml -n test-migration
```

### 3. Run Pre-Migration Check

Before migration (or to capture current state):

```bash
./pre-migration-check.sh test-migration /tmp/migration-check/pre
```

This captures:
- Full RayCluster specs as JSON
- Summary of containers, initContainers, env vars, volumes
- Related resources (Services, Secrets, NetworkPolicies, etc.)

### 4. Trigger Migration

The migration is triggered automatically when the KubeRay operator detects the `ray.openshift.ai/oauth-finalizer` on a RayCluster.

If testing manually, you can add the finalizer:

```bash
kubectl patch raycluster <name> -n test-migration --type=merge -p '{"metadata":{"finalizers":["ray.openshift.ai/oauth-finalizer"]}}'
```

### 5. Run Post-Migration Check

After migration completes:

```bash
./post-migration-check.sh test-migration /tmp/migration-check/pre /tmp/migration-check/post
```

This verifies:
- CodeFlare items were removed
- Custom items were preserved
- Generates pass/fail report

## Scripts

### pre-migration-check.sh

```
Usage: ./pre-migration-check.sh [namespace] [output-dir]

Arguments:
  namespace   - Kubernetes namespace (default: test-migration)
  output-dir  - Directory to save captured state (default: /tmp/migration-check/pre)
```

### post-migration-check.sh

```
Usage: ./post-migration-check.sh [namespace] [pre-migration-dir] [output-dir]

Arguments:
  namespace          - Kubernetes namespace (default: test-migration)
  pre-migration-dir  - Directory with pre-migration data (default: /tmp/migration-check/pre)
  output-dir         - Directory to save post-migration data (default: /tmp/migration-check/post)

Exit codes:
  0 - All checks passed
  1 - One or more checks failed
```

## Requirements

- `kubectl` configured with cluster access
- `jq` for JSON processing
- Bash 4.0+

## CI Integration

These scripts can be integrated into CI pipelines:

```bash
#!/bin/bash
set -e

# Setup
kubectl create namespace test-migration || true
kubectl apply -f testdata/ -n test-migration

# Wait for RayClusters to be created
sleep 10

# Capture pre-migration state
./pre-migration-check.sh test-migration /tmp/pre

# Deploy new KubeRay operator (triggers migration)
# ... deployment steps ...

# Wait for migration to complete
sleep 30

# Verify migration
./post-migration-check.sh test-migration /tmp/pre /tmp/post

# Cleanup
kubectl delete namespace test-migration
```

## Troubleshooting

### Migration not triggered

Check if the finalizer is present:
```bash
kubectl get raycluster <name> -n test-migration -o jsonpath='{.metadata.finalizers}'
```

### Pods not restarting

The migration uses suspend/unsuspend to trigger pod recreation. Check:
```bash
kubectl get raycluster <name> -n test-migration -o jsonpath='{.spec.suspend}'
kubectl get pods -n test-migration -l ray.io/cluster=<name>
```

### Check migration events

```bash
kubectl get events -n test-migration --field-selector involvedObject.name=<name>
```
